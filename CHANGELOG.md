# Changelog

Each release of fxbot, newest first. A release that adds migrations, bumps libfx, or needs a step by hand opens with **Before upgrading**. Lines for the next release collect under Unreleased. GitHub Releases and Settings show a short version of each section.

## Unreleased

**Before upgrading.** Migration `0011_onboarding` adds `onboarding_step` and `onboarded_at` columns to `settings`. An install with a bot, a plugin, or a provider is marked done, so it never sees first-run setup. Migration `0012_looks` adds `mood`, `head`, `face`, `outfit`, and `tint` columns to `profiles`. Every bot keeps its shape and its color, drawn the new way.

- **Bots have a new look.** Big dark eyes, soft color, and more shapes: the fourteen you know and eighteen more, such as toast, cat, frog, and ghost.
- **A feeling, and things to wear.** Give a bot a feeling, from bright to doubtful, and something for its head, its face, and its body, each cut to fit its shape, in the bot's own color, black, or white. A blazer on a heart sits as well as a blazer on a circle.
- **A bot shows what it's doing.** It focuses and hops while it works, looks at you and bobs while a call waits on an answer, smiles when it finishes, and sleeps when it has no provider. Its head seems to turn as it watches the pointer, and a click gets a squish and a smile. With reduced motion on, it holds still.
- **A new bot screen.** Pick from tabs for **Shape**, **Color**, **Feeling**, **Head**, **Face**, and **Body**, with each choice drawn on your bot, or tap **Surprise me**. It's the same in first-run setup and on a bot's edit page, and on a phone the bot stays in view as you scroll.
- **Chat rooms 0.3.1, Messages 0.1.1, Permissions 0.1.1, and Pages 0.2.1** show each bot's whole look. Update them from **Plugins**.
- **For plugins:** pass a whole bot to `Blob`, as in `<ui.Blob {...bot} size={24} />`, and it shows what the bot wears and is doing, and an older fxbot ignores what it doesn't know. `waiting` on a bot is true while a `tool.before` hook's `{ wait }` holds one of its calls.
- **For the SDK:** a `Profile` gains `mood`, `head`, `face`, `outfit`, `tint`, and `waiting`, and `moods`, `heads`, `faces`, `outfits`, and `tints` list what each takes. `shapes` has 32, and `colors` keeps its names with softer values.
- **Pages.** A bot writes a report, a guide, or a plan to read outside the chat, from the new `pages` plugin, in **Essentials**. A card in its chat opens the page, and the library keeps it, with every version. When a page needs more than text, such as a chart with filters, the bot writes it in HTML, in a frame of its own. A task list has boxes you tick, and the bot sees them. An HTML page saves what you do on it, a routine can send it new numbers without rewriting it, once you allow it, and a button on a page can draft a message to the bot.
- **First-run setup.** A new install walks through plugins, a provider and a model, and a first bot, then opens its chat. It saves each step, so a restart comes back to it, and **Skip for now** is on every step.
- **Essentials.** A pack of what most people want from fxbot, at the top of **Browse**, with **Add the other 3**. Each plugin in it stays its own.
- **fxbot knows which plugins can run on it.** A plugin that needs a newer fxbot says so on its page, and **Add** stays off. A newer version that needs a newer fxbot shows **Needs fxbot** in place of **Update available**, and the one you have keeps running.
- **Unsupported.** When a release breaks something a plugin uses, the plugin doesn't run, its tab says why and how to fix it, and the rest of fxbot starts as usual. Its files, settings, and tables are kept, and an update that fits brings it back.
- **Settings warns before an update,** naming the plugins that wouldn't run on the new release.
- **A plugin's page that fails to load says so** on its tab, where before only the browser's console knew.
- **Each of fxbot's plugins says the oldest fxbot it runs on,** so they show **Update available** once, with nothing to do but update.
- **For plugins:** `fx.library.replace` changes a document in place, the `library.removed` hook says an item went, and `app.libraryItem` is a place in an item's preview. A plugin can be named `pages`, though not have a route at its root. See the [plugin API](https://fxbot.sh/sdk/reference/plugin-api/).
- **For plugins:** `minFxbot` in `plugin.json` is the oldest fxbot a plugin runs on, and fxbot publishes what each release broke in [plugin-breaks.json](https://fxbot.sh/plugin-breaks.json). See [Which fxbot it runs on](https://fxbot.sh/sdk/reference/plugin-api/#which-fxbot-it-runs-on). It adds no migration.

## 0.6.0 (2026-11-06)

**Before upgrading.** Migrations `0009_time_zone` and `0010_turns_at_once` add `time_zone` and `turns_at_once` columns to `settings`. A time zone set in dreams moves to **Settings** › **General**: the first browser to open fxbot sets it there, so check it if yours should be another.

- **Choose what each bot can do alone,** from the new permissions plugin, on fxbot's list. Each bot has a mode: **Ask** asks you before anything but a safe tool, **Auto** has a reviewer model check risky calls against what you said, and **Yolo** runs everything. A call that needs you shows a card above the message box, with the exact action, and **Approve once**, **Always allow**, and **Deny**. A card from work you didn't start expires after 30 minutes, and the action doesn't happen. The reviewer can be another provider and model. It adds no core migration. See [Choose what a bot can do alone](https://fxbot.sh/docs/how-to/choose-what-a-bot-can-do-alone/).
- **Removing a provider stops what's running on it.** A turn stuck on a provider could go on calling it with the old key until fxbot restarted, and **Remove** could hang. Now it ends those turns first, deleting a bot ends all its turns, in rooms and routines too, and a key that's replaced or removed stops working at once.
- **A bot stuck on a provider that keeps refusing says so.** A turn that gets only refusals, such as a rate limit, ended up silent for as long as fxbot ran. After 5 minutes it now stops, with the reason in the chat. A slow model that refuses nothing isn't touched.
- **More bots can work at once.** Up to 32 turns run together, up from 4, so four long commands no longer stop your other bots. **Turns at once** in **Settings** › **General** changes it, from the next time fxbot starts.
- **Routines,** from the new routines plugin, on fxbot's list. Ask a bot "every weekday at 8, summarize my calendar", and it saves a routine, which runs on time in a session of its own with everything the bot has: its computer, MCP servers, skills, memories, and library. It tells you in its chat, with the files it saved, and stays quiet when there's nothing to say. Each bot's settings list its routines and their runs, with a switch, **Run now**, **Stop**, and **Remove**, and **Settings** › **Routines** has the limits, such as how long a run takes. See [Give a bot a routine](https://fxbot.sh/docs/how-to/give-a-bot-a-routine/).
- **A time zone** in **Settings** › **General**, which the first browser to open fxbot sets, and plugins use.
- **Dreams 0.2.0** uses that time zone, in place of a setting of its own. Update it from **Plugins**.
- **Bots work together,** from the new messages plugin, on fxbot's list. A bot messages another with one tool, and the message lands in the other's own chat, where it joins what the bot is doing or wakes it, so you see the work where it happens. A reply is a message too: a bot can say "got it", do the work, and send the result. A conversation has a budget of 20 messages, a no-reply message can't be answered, and **Open conversations**, in **Settings** › **Messages**, shows each conversation as one thread, with **Stop**. It adds no core migration. See [Let bots work together](https://fxbot.sh/docs/how-to/let-bots-work-together/).
- **Bots' messages stay out of your way.** A message between bots is a small pill in the chat, with the bot's face, such as **2 received, 1 sent · Philly**, that stacks up between what you and the bot say, and opens with a click. What a bot says to you stays in view.
- **Tag any bot.** With the messages plugin, `@` in a bot's chat lists the bots it can reach, and the one you pick is a chip with its face, right in your message, as in a room. The bot then knows exactly which one you mean, even with two of one name.
- **A message to a working bot joins what it's doing.** You no longer wait for a turn to finish: your words reach the bot where it is, and show there in the chat, among its steps. A message waits for a running tool, and a picture of yours ends the turn and runs next.
- **Stop in a bot's chat.** While a bot works and the box is empty, the send button is **Stop**. It doesn't wait for a running tool, and what you'd sent that the bot hadn't read runs next.
- **`chat_history` has the whole chat.** A bot can now search and read its own thinking and tool calls with their results, in the order they happened, as well as what was said, and each result says who it's from, so another bot's words don't read as yours. Older chats keep what they had: messages. It adds no migration.
- **Your messages are readable in every bot's color.** A bubble keeps the bot's hue, in a shade dark enough for white text, in place of dark text on mid-tones such as blue and green.
- **Each plugin has a tab in Settings.** Everything about a plugin is on one page: its switch, bots, settings, log, updates, and **Remove**, with a plugin's MCP servers and their tools right there. The pencil on each row in **Plugins** is gone, along with the dialogs it opened: a plugin's name still opens its page, whose **Settings** goes to its tab. For plugins: `app.settings` now draws at the top of that tab, which every plugin has.
- **Computer 0.3.1:** its part of Settings drops a heading its tab now has, a cancelled turn now really stops its command, which went on running until its own timeout, and a page open while fxbot restarts keeps the computer in the bot's panel. Update it from **Plugins**.
- **For plugins:** `fx.timeZone()` answers the owner's time zone, `fx.bots.on(bot)` says whether the plugin is on for a bot, and `fx.library.list(bot, session)` answers what one chat saved. `fx.chats.send` takes `shown`, what the chat shows in place of the text the model gets, and tool calls and the tool hooks carry the `messageId` of their turn. A plugin in `FXBOT_PLUGIN_DIRS` keeps its MCP servers when fxbot starts again. Before, they came loose from it, showing as plugins of their own, and stayed when it was removed.
- **For plugins:** `fx.chats.send` takes `label`, who the chat says a message is from, and `steer`, to join a running turn, and answers `joined`. `fx.chats.cancel(bot)` with no session stops a turn the plugin started in the bot's own chat. `turn.end` says `cancelled`, and in a bot's own chat `turn.start` comes when a turn that waited behind another starts. The stream has a `user_message` line for a message that joined a turn. For the SDK, `profiles.stop(id)` and `POST /api/profiles/<id>/stop`.
- **For plugins:** a `tool.before` hook can answer `{ wait }`, for what takes longer than a hook may, and gets `callId`, `description`, and `safe`. A tool can say it's `safe`. `fx.models.ask` makes one tool-free request, `fx.chats.ownerSaid` reads what the owner wrote, `app.chat` draws above the message box, and a page's `ui` has `ModelField` and `NativeSelect`. `app.box` replaces the message box in a bot's chat, `app.said` draws part of a message, and `app.fold` folds messages into a pill.
- **Set up with your AI agent.** The home page offers a line to give your agent, which sets fxbot up from [agent-setup.txt](https://fxbot.sh/agent-setup.txt): it checks the machine, asks before it installs anything, and leaves your keys and sign-ins to you. **Copy all docs**, on each page of the docs, copies them all in one go, and [Set up with your AI agent](https://fxbot.sh/docs/tutorials/set-up-with-an-agent/) lists `llms.txt` and `llms-full.txt`, as the home page's footer does.
- **Reach it over SSH.** [Reach it from other devices](https://fxbot.sh/docs/how-to/reach-it/#over-ssh) has a way in for a machine with no screen.

## 0.5.0 (2026-11-05)

**Before upgrading.** Migration `0008_default_bot` adds a `default_profile` column to `settings`. The update starts the database container again once, with your data, because its health check changed. On Docker, a start takes about a minute: until your next update on Docker 25 and newer, and always below 25. If `setup.sh` stopped on your machine, run it again.

- **A default bot.** Pick one in Settings › General, and launching fxbot opens its chat, where it left off. For the SDK, `Settings` gains `defaultProfile`, and each `Profile` `isDefault`.
- **Plugin icons.** Each plugin has an icon of its own, a soft shape on a tinted tile in two hues, drawn from who made it and its name, so it looks the same everywhere: in **Plugins**, in Settings, and in the sidebar. For the SDK, each plugin and card has `iconKey`, and `@fxbot/sdk/client` exports `pluginIcon(key)`, which draws it. A plugin's `app.nav` button with no `icon` shows the plugin's icon.
- **A plugin directory** at [fxbot.sh/plugins/](https://fxbot.sh/plugins/): the plugins fxbot vets, with a search box, a card each with its icon, and a page each that says what it carries and how to add it.
- **Stopping takes 30 seconds at most.** fxbot gives running chats 30 seconds to finish, then exits, and a chat still running goes on where it stopped when it starts again. Before, a reply that never ended kept fxbot from stopping, and in a checkout kept `npm run dev` from restarting its API. Plugins now stay on until the running chats finish, so their tools work to the end. For the SDK, `close()` closes the agents before the plugins and MCP connections.
- **Plugins:** each plugin's row in Installed and Browse shows a line about it under its name: the first sentence of its description, up to 100 characters and two lines. Browse lists only the plugins you haven't added, and an installed plugin's name opens its page, as Browse shows one, read from the files it runs, with **Settings** in place of **Add**. For the SDK, `plugins.contents(id)` and `client.plugins.contents(id)` answer an installed package's page, and a `PackagePreview`'s `source` can be a local folder.
- **Settings in tabs:** General, Providers, Memory, Plugins, and About, each at its own address, and a tab for each plugin that draws in Settings, such as Computer. About has the version, updates, and links.
- **/fresh starts a chat over,** from the new fresh plugin, on fxbot's list. `/fresh` and where you want to go, in a bot's chat, has the bot summarize the chat, keeping what bears on your words, and start a new chat from it with your message. The chat shows a **Started over** card, and the old chat stays above it. See [Start a chat over with /fresh](https://fxbot.sh/docs/how-to/start-fresh/).
- **A provider switch** now stops a reply still running in the old chat, and pages open on the bot follow it to the new chat without a reload. A summary that fails gives up after 2 minutes, not 4.
- **A computer for a chat room.** The new chat-rooms-computer plugin, on fxbot's list, gives a room a computer its bots share, taking turns, from a screen button at the top of the room. It needs the computer and chat rooms at 0.3.0: update them from **Plugins**. See [Give a room a computer](https://fxbot.sh/docs/how-to/give-bots-a-computer/#give-a-room-a-computer).
- **Computer 0.3.0:** the Computer screen draws an arrow where each bot last pointed, and other plugins can name computers of their own. Its screen is at `/computer/computers/<key>`, and the old address still works.
- **Chat rooms 0.3.0:** other plugins can ask which room a session is for, and add to a room's header.
- **Bots dream,** from the new dreams plugin, on fxbot's list. Each night a bot goes over its day: it saves what's worth remembering as its own memories, citing the turns they came from, and writes a way of working that worked down as a skill, at most one a night. **Dreams**, in each bot's settings, is a journal of each change, with **Undo**, and **Dream now**. Its tables are its own: core has no migration for it. See [Let bots dream](https://fxbot.sh/docs/how-to/let-bots-dream/).
- **`setup.sh` takes the machine it finds.** It reads the versions of podman, Docker, and Compose, and sets up what's missing, so it works beside Compose v1 and podman-compose, on Debian 12 and Ubuntu 22.04, and on distros built on Debian or Ubuntu. fxbot needs Compose 2.26 or newer: the machine's, the distro's package, or Compose's own release, which it downloads into `/opt/fxbot` and checks against its hash. Where the distro's podman is older than 4, it installs Docker. An install that stopped before its first start starts over from the newest release. `fxbot up` now says why it failed, and `fxbot compose` runs Compose on the install's files.
- **A new install works on stock Debian and Ubuntu again.** Their Compose packages refused `start_interval` on podman, and podman's network parts weren't installed. `start_interval` moved to `compose.docker.yaml`, which the `fxbot` command adds on Docker 25 and newer.
- **fxbot runs on Docker again.** From 0.4.0, the app stopped as it started on Docker, with `uv_os_homedir returned ENOENT`.
- **For plugins:** `app.settings` makes a tab, at `/settings/plugins/<plugin>`. A `message` hook can answer `{ startOver: { ask } }`, to start the bot's own chat over before the message runs, and `plugin.json` can list `commands` for the `/` list. `fx.provide` and `fx.need` let one plugin use another it names under `needs`, and `app.slot` fills a place another plugin's page leaves with `Slot`. `fx.memories` reads, saves, and removes a bot's memories as the bot's own, and `fx.skills.set` gives one bot skills the plugin writes. `turn.end` carries `error` when the provider answered with an error, too.
- **For the SDK:** a chat that starts over ends its streams with a `moved` line naming the new session, and `stream` and `client.stream` take `session`, the session a cursor is in.

## 0.4.0 (2026-11-04)

**Before upgrading.** Migration `0006_plugins` adds a `plugin` column to `sent` and a `plugin_sessions` table. Migration `0007_one_kind_of_plugin` renames the add-ons' tables: `addons` to `plugins`, `addon_secrets` to `plugin_secrets`, `profile_addons` to `profile_plugins`, and `skills.addon_id` to `plugin_id`. Your MCP servers and skills carry over as plugins. Only the plugins fxbot vets show from now on: to search GitHub's MCP registry and skills.sh, or add by address or repository, turn on **Show unvetted plugins** in Settings. For SDK users, the add-on calls and routes are renamed: see the last item.

Chats move into the database on the first start. fxbot backs up once, before the migrations, into a folder named `<date>-before-0006_plugins`, then copies each chat from `FXBOT_DATA/sessions` into tables of its own, at about 6,000 lines a second, and renames the folder `sessions.moved`. Delete that folder once you're sure: `sudo rm -r /var/lib/fxbot/data/sessions.moved`. To go back to 0.3, restore that backup: it holds the database before the migrations and the chats' old files. A chat that can't be moved stops the start and names it, with its files untouched, and the update goes back to the release before.

- **One kind of plugin.** Add-ons are plugins now, with one page, **Plugins**, where the Skills, MCP, and Plugins tabs are one **Browse**. A plugin carries any mix of code, MCP servers, and skills, and each row and card says what it carries. The MCP servers and skills you have show as plugins that carry one thing.
- **Vetted by default.** Browse shows fxbot's picks, tagged **fxbot**. **Show unvetted plugins**, in Settings, adds GitHub's MCP registry, the official one, skills.sh, adding a server by address, and any plugin on GitHub. While it's off, fxbot asks none of those, and refuses to add from them.
- **Plugins with code.** A plugin's code runs inside fxbot: it can hook into each message, each chat's instructions, every tool call, and each turn's start and end, and add tools, routes, tables of its own, settings, and places in the app, from a screen and a sidebar group to a control beside the message box. Its page shows the code that runs before you add it, and it stays pinned to that commit until you update it. Its MCP servers show in its settings, and follow its switch and its bots. For writing one in a checkout, `FXBOT_PLUGIN_DIRS` loads plugin folders, again each time they change.
- **Chat rooms**, fxbot's first plugin with code: rooms where several of your bots talk with you, each answering every message once, in turn.
- **herdr**, its second: bots see the coding agents [herdr](https://herdr.dev) runs, and read what their panes show.
- **A computer for each bot**, a plugin: a Linux machine where the bot runs commands, keeps files, and saves what it makes to its library. Computers run in the machine's own podman or docker, rootless for a user of their own, start on a bot's first call, and stop when idle; a firewall keeps them to the internet. Two fxbots on one machine share the engine, and each leaves the other's computers be. See [Give bots a computer](https://fxbot.sh/docs/how-to/give-bots-a-computer/).
- **The computer sets itself up.** Adding the computer plugin is all you do: the machine sets up its engine, a rootless podman or docker for a user of its own with a firewall, and starts fxbot again, while Settings shows it working. The machine's `fxbot` command gains `fxbot computer on|off`, which does it, and the plugin API gains `fx.machine`, through which the plugin asks. A checkout run as root sets up the same way; one run as another user still shows the command.
- **A desktop on each computer.** Each bot's computer has a desktop, with Chromium, a file manager, and a terminal. Its Computer screen shows the desktop live, and the terminal the bot types in. **Take over** gives you the mouse and keyboard, and **Hand back** returns them. A bot that needs you for a sign-in asks with `computer_ask_owner`, and carries on when you hand back. The computer's new tools: `computer_desktop` clicks, types, and takes screenshots, which show in the reply; `computer_terminal` answers programs that ask; and `computer_write_file` changes one place in a file. Bots drive Chromium with agent-browser, and desktop apps by their accessibility trees with agent-desktop, and the computer's three skills and a few lines in each chat's instructions say which to use when. `$computer`, or the screen button beside the message box, points a message at it. A bot's panel shows its computer's screen, small and live, above **Details** and **Library**, or **Idle** with a button that starts it. The image grows to about 1.2 GB.
- **Plugins that need others.** A plugin's `plugin.json` can name plugins it needs, each with an object for that one. Its page says so, and Add waits for them; a plugin others need can't be removed while they're added. The plugin API gains `fx.dependents()` and its event, `fx.library.read` and `save`, `fx.skills.files`, and `fx.socket`, a WebSocket of the plugin's own; and on the page, `app.botPanel`, and a composer control's `setDraft` that takes a function. A plugin at the root of its repository can be added too.
- The docs have [Add a plugin](https://fxbot.sh/docs/how-to/add-a-plugin/), and the SDK's pages [Write a plugin](https://fxbot.sh/sdk/how-to/write-a-plugin/) and the [Plugin API](https://fxbot.sh/sdk/reference/plugin-api/). Core and add-ons is now [Core and plugins](https://fxbot.sh/docs/explanation/core-and-plugins/).
- **The docs on Starlight.** fxbot.sh's docs and the SDK's pages gain search, and each page **Copy Markdown** and **Open** in ChatGPT or Claude. `llms.txt` lists the pages for models, and `llms-full.txt` has them all in full.
- **Health checks every 30 seconds**, not every 3. Each one cost podman about 30 ms of CPU, so an idle install spent about 3% of a core on them. Starts are as quick as before: `fxbot` runs the checks every 2 seconds while it waits. The update to this release, run by the earlier `fxbot`, waits about 30 seconds longer for it to start.
- **Chats in the database.** Each chat moves from files into Postgres, through Workflow's Postgres World, so a long chat costs no more than a short one. On a chat of 25,000 lines, two open pages cost the server about a quarter of a core while nothing happened, and now cost nothing. A message is accepted in about 25 ms instead of 1.2 s, the chat loads in under a second instead of 3, and it takes about a tenth of the disk. The page also closes its stream while it's hidden, in a background tab, a minimized window, or a locked phone, and catches up when it's shown. fxbot's image grows by about 60 MB, for Workflow's packages.
- **A chat opens at its end.** Opening a chat used to scroll through every turn as its lines arrived, for seconds on a phone. It now appears once, whole and at its end, instead of filling in piece by piece, with the newest 20 turns, and 20 earlier ones each time you scroll near the top. The rest of the app appears with it. The chat's lines are gzipped on the way, about 8 times smaller for a real chat. For the SDK, `client.stream` takes `onCaughtUp`, `fxbot.streamEnd` gives a chat's newest cursor, and the stream's `x-fxbot-end` header carries it.
- **Memories moved** to the bot's edit screen, under its settings. The bot's panel keeps **Details** and **Library**.
- The SDK's `close()` waits for the save of a reply that just finished, so a script can close right after a turn. A reply that can't be saved, such as one whose bot was just deleted, is logged instead of stopping the process.
- **Renamed, for the SDK and the HTTP API.** `fxbot.addons.*` and `client.addons.*` are `fxbot.plugins.*` and `client.plugins.*`. `/api/addons/…` is `/api/plugins/…`, and `/api/profiles/:id/addons/:id` is `/api/profiles/:id/plugins/:id`. The types follow: `Addon` is `Plugin`, `McpAddon` `McpPlugin`, `SkillAddon` `SkillPlugin`, `AddonRef` `PluginRef`, `AddonPreview` `McpPreview`, `AddonCard` `McpCard`, `AddonSearch` `McpSearch`, `AddonSecrets` `PluginSecrets`, `AddonMark` `PluginMark`, `AddonInfo` `RegistryInfo`, `AddonFrom` `RegistryFrom`, and `AddonTool` `McpTool`. Settings gain `unvetted`.

## 0.3.0 (2026-11-02)

**Before upgrading.** fxbot now runs as containers, and Settings' Update in 0.1 or 0.2 can't make that move. Run `setup.sh` again instead, the command under Install: it stops the old service, copies its database into the database container, and starts the containers on the same chats, key, and settings. The old files and database stay until you remove them, and `sudo fxbot status` says how, or how to go back. Migration `0005_memories` adds memories and vectors, and needs pgvector, which the database container has: on the machine's own Postgres, it stops and says to run `setup.sh`. The local embedder downloads its 310 MB model on its first start, holds about 380 MB, and fills in vectors for existing messages in the background. A checkout moves its database too: see the README's Run from a checkout.

- **Containers.** `setup.sh` installs fxbot as containers, with podman, or docker when only docker is installed: fxbot's image from ghcr.io, for amd64 and arm64, pgvector's Postgres image, and the local embedder. It no longer installs Node or the distro's Postgres. `sudo fxbot` runs them: `status`, `logs`, `update`, `up`, `down`, `restore`, `rotate-key`, and `embedder`.
- **Updates through the machine.** Settings' Update asks the machine, which starts the new release and waits until it answers. If it doesn't, the old release comes back by itself, on the backup taken before the new one's migrations, and Settings shows why. The database keeps running, and running chats finish first.
- **Memories.** Each bot keeps what it learns: it saves one fact at a time with `memory_save`, finds them with `memory_search`, and removes wrong ones with `memory_forget`, which the chat shows as sentences. The newest are in its instructions on every turn, within 2% of the model's context window, and the owner sees, adds, edits, and deletes them in the bot panel's Memories tab.
- **Memory search by meaning.** Memory search and `chat_history` match by meaning as well as by words. The vectors come from a local embedder (EmbeddingGemma 2 on the CPU, or Qwen3-Embedding on an NVIDIA GPU), from a provider's embedding model, or from none, picked in Settings' Memory search, or with `sudo fxbot embedder`. Chat messages get vectors too, from their first 8,000 characters, which Settings can change or turn off.
- `sudo fxbot rotate-key` seals every stored key and token again under a new key, and keeps the old key until you remove it.
- A checkout's database and local embedder run from `deploy/compose.dev.yaml`. `npm run update` is gone: a checkout updates with git.
- The server listens on `FXBOT_HOST`, 127.0.0.1 by default.
- fxbot reads its own lists of MCP servers and skills from its site, https://fxbot.sh, every hour, so new picks show up between releases. Before, it read them only with `FXBOT_LISTS_URL` set, which now points it at another site.
- The website's top bar and the README link to the Hackers in the Loop community on [Discord](https://discord.gg/3Qs2uejUf9).

## 0.2.0 (2026-11-02)

**Before upgrading.** Migration `0002_model_lists` adds a table that keeps each provider's model list, `0003_registry_entries` adds two that keep a copy of GitHub's MCP registry, and `0004_skills` adds one for skills. Chats and add-ons carry on.

- **Skills.** Bots use [Agent Skills](https://agentskills.io): instructions for a kind of task, read only when a task needs them. The Add-ons page's Skills tab lists fxbot's own picks (show-me, frontend-design, and grilling), tagged **fxbot**, and searches skills.sh, tagged **skills.sh**. A skill installs as skills.sh installs it, from its GitHub repository at the commit its page showed. Each bot's instructions list its skills, within 1% of the model's context window, and a `skill` tool reads one, which the chat shows as "Read a skill". In a chat, `$`, or `/` at the start, lists the bot's skills: the one picked goes with the message as a chip, so the bot has it without deciding to. Skills go to all bots or chosen ones, like MCP servers, and are marked **Update available** when their files change upstream. Nothing in a skill runs.

- The Add-ons page is a search above four tabs: Installed, Skills, MCP, and Plugins. MCP searches GitHub's MCP registry, which fxbot mirrors every hour, and **Search everything** adds the official registry's unmoderated results. Each entry opens on a page that shows its host (in red when it isn't on the publisher's domain), how it signs in, the keys it needs, and where it comes from, before **Add**. Adding by address is still there, under MCP. Plugins says they aren't in fxbot yet.
- fxbot ships with its own list of MCP servers, starting with alphaXiv and Keiro, tagged **fxbot** and listed first. With `FXBOT_LISTS_URL` set to the site that publishes it (the website's `mcp-registry.json`, beside `skills-registry.json`), fxbot reads it every hour, so the lists can grow between releases. Other cards are tagged **GitHub registry** or **Official registry**, and a server on more than one shows once, as fxbot's.
- An installed server from a registry is marked **Update available**, **Deprecated**, or **Removed from the registry**, and nothing changes by itself. **Update to** shows what the newer version changes, and moves only on **Update**.
- Past 40 tools reaching the bots, the Add-ons page says how many.
- A server still connecting when fxbot stops no longer writes to the database after it closes.

- Model lists outlast restarts. fxbot keeps each provider's list in Postgres and answers with it at once, fetching a fresh one behind the answer when it is over 5 minutes old; a failed refresh keeps the old list ([#5](https://github.com/iammrduncan/fxbot/issues/5)).
- The chat shows how each reply came about, in order: thinking, tool calls, and text between them. A tool call reads as a sentence, such as "Searched the library" or "Ran linear_create_issue", and opens on its input and result; a failed one says so in red. Two or more steps in a row fold under one line, such as "Thought and used 2 tools", open while the bot works. Before, tool calls didn't show at all, and the thinking showed as one block.
- The model field is a picker that opens on the provider's whole list, the current model marked, and narrows as you type. Before, the browser's suggestions showed only the model already chosen. A model id the list lacks can still be typed in, and Clear empties the field.
- `setup.sh` stops, and says why, when another fxbot already holds its names: a database `fxbot`, a key in `/etc/fxbot`, or port 8787.
- A checkout's `npm run dev` runs its API on port 8788, so it runs beside a release install on one machine.
- The README shows how to serve fxbot at its own tailnet name, such as `bot.<tailnet>.ts.net`, as a Tailscale Service.
- fxbot has a website with its docs, in `packages/website`. `npm run build-site` builds it into `out/` and checks its links.

## 0.1.0 (2026-11-02)

The first release.

- **Bots and chats.** Bots drawn as animated blobs, each with a streaming chat that survives reloads and restarts, image and text attachments, and a `chat_history` tool that searches its own past.
- **Providers.** ChatGPT, Grok, and Vercel accounts by device code, API keys, and local model servers, with every key and token sealed in Postgres.
- **The library.** Every file the chats hold, searchable, for people and bots.
- **An installable app** for phones and desktops.
- **MCP servers.** Tools from any remote MCP server, signed in with OAuth or a key, for all bots or chosen ones, with only the tools you allow.
- **Releases.** `setup.sh` installs a release, and Settings or `npm run update` moves to the next one. The database migrates forward, with a backup first.
